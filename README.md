This repository contains a workflow example that illustrates how 834 enrollment data moves across UKG, an EDI gateway, and downstream eligibility systems such as Facets, QNXT, and SAS. The swim lane is designed to show the real‑world sequence of events involved in generating, validating, transmitting, loading, and reconciling 834 transactions from the employer’s HRIS all the way through carrier production systems. It highlights the checkpoints, dependencies, and error‑handling steps that an EDI analyst manages daily to keep eligibility accurate and prevent downstream issues with claims or member coverage. This file serves as a portfolio example of how I analyze, troubleshoot, and maintain end‑to‑end EDI workflows in a multi‑system environment.
